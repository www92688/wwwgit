## 一、引言

本文档依据需求文档进行系统概要设计，确定系统的总体架构、模块划分、模块间关系、关键接口与数据结构，作为后续详细设计与编码实现的依据。本文档不涉及具体算法实现细节（属于详细设计阶段）。

以下决策已与需求方确认，作为本设计的输入前提：

| 决策项 | 结论 |
|--------|------|
| 桌面技术栈 | Python 3.x + PySide6（Qt for Python） |
| 视频处理引擎 | FFmpeg（子进程调用）+ OpenCV |
| AI 能力实现 | 本地模型为主；架构上抽象推理接口，预留云端扩展 |
| 自动搜索比对定位 | 尽力而为 + 可降级：平台不可用时明确提示，引导改用手动对比 |

## 二、总体架构设计

### 2.1 架构风格

采用 **「分层架构 + 插件化」**：

- 纵向分四层：**表示层 → 业务逻辑层 → 核心服务层 → 外部资源层**；
- 两处插件化扩展点：**平台适配插件**（采集与搜索）、**去重手法模块**；
- AI 推理通过抽象接口隔离，本地实现与未来云端实现可替换；
- 长耗时任务（下载、预处理、去重）统一由 **任务调度中心** 编排，UI 不直接驱动任务。

依赖规则：

1. 上层可依赖下层，禁止反向依赖；
2. 业务模块（M1/M2/M3）之间不直接调用对方内部实现，跨模块协作通过明确定义的服务接口或任务调度中心完成；
3. 对外部资源（FFmpeg 可执行文件、AI 模型文件、网络平台）的访问只能经由核心服务层封装进行。

### 2.3 运行时结构（进程与线程模型）

单进程应用，内部采用「多线程 + 子进程」模型：

| 执行单元 | 职责 | 说明 |
|----------|------|------|
| UI 主线程 | 界面渲染与交互 | 禁止执行任何耗时操作，保证界面响应 ≤1s |
| 工作线程池 | 下载、预处理、去重任务 | 并发下载数默认 3、可配置（满足 ≥3 并行要求）；处理类任务并发数独立可配 |
| FFmpeg 子进程 | 转码、抽帧、探测媒体信息 | 通过 `ffmpeg` / `ffprobe` 子进程调用，避免阻塞与崩溃连带 |
| AI 推理线程 | 模型加载与推理 | OpenCV DNN / ONNX Runtime 推理释放 GIL，不阻塞 UI 与其他任务 |

跨线程通信统一使用 Qt 信号槽（队列连接），进度与状态消息由工作线程回传 UI。

启动性能设计（启动 ≤5 秒）：主窗口先展示，SQLite 延迟打开，AI 模型懒加载（首次使用对应功能时才加载），平台插件按需初始化。

### 2.4 技术选型清单

| 类别 | 选型 | 用途 |
|------|------|------|
| GUI 框架 | PySide6 | 界面、信号槽、多线程、i18n（Qt Linguist） |
| 视频引擎 | FFmpeg（子进程）+ OpenCV | 编解码、滤镜、抽帧、图像处理 |
| AI 推理 | ONNX Runtime（建议） | 统一以 ONNX 格式分发检测/修复/特征提取模型 |
| 数据库 | SQLite（Python 内置 sqlite3） | 单文件持久化 |
| 打包 | PyInstaller + Inno Setup | 生成 .exe 安装包，内置 FFmpeg 与模型文件 |
| 日志 | logging + 滚动文件 | 本地日志排查 |

### 3.2 M1 素材采集模块

| 子模块 | 职责 | 备注 |
|--------|------|------|
| M1.1 搜索服务 | 接收多关键词批量搜索请求；读写历史搜索词（经 S3）；将搜索请求分发给各启用的平台插件并汇总结果 | 结果统一为标准 `VideoMeta` 结构 |
| M1.2 结果筛选器 | 按 时长范围 / 画质（分辨率）/ 文件大小上下限 / 水印情况（有/无/不限） 对搜索结果做元数据过滤 | 水印情况依据平台返回元数据，无法判定时标记"未知"并按"不限"处理 |
| M1.3 下载队列管理 | 维护下载任务队列；并发控制（默认 ≥3）；单次搜索下载数量上限控制（达到上限自动停止并提示）；进度回调；断点续传状态管理（分片临时文件 + 已完成字节数持久化） | 经 M4 执行 |

| M1.5 网络环境检测 | 国外平台开启前探测外网访问能力（连通性探测目标站点）；不具备能力时返回明确状态供 UI 弹窗提示 | 结果缓存，避免频繁探测 |

### 3.3 M2 视频预处理模块

| 子模块 | 职责 | 备注 |
|--------|------|------|
| M2.1 流水线编排 | 将用户勾选的处理项组装为有序流水线执行；单个/批量模式；产出结果列表（成功/失败/跳过） | 经 M4 执行 |
| M2.2 水印处理器 | 自动模式：调用 S2 检测水印位置 → 生成遮罩 → 调用 S2 图像修复擦除；手动模式：用户框选区域生成固定遮罩 → 修复 | 修复后画面不得出现明显黑块/模糊斑块，提供预览 |
| M2.3 字幕处理器 | 硬字幕：同水印处理流程（检测字幕区域→修复），支持中英文；软字幕：经 S1 直接剥离字幕轨道 | 软/硬字幕自动判别 |
| M2.4 画面变换器 | 裁剪指定画面区域；比例调整（16:9 / 9:16 / 1:1 等，含裁切或加黑边策略选择） | 经 S1 的 FFmpeg 滤镜实现 |
| M2.5 音频处理器 | 去除原始音频轨道 | FFmpeg `-an` 实现 |
| M2.6 效果预览 | 对处理后片段做快速低耗预览（抽帧或短片段转码） | 供用户确认效果 |

输出约定：MP4 格式；存放于原文件同目录；文件名追加 `_cleaned` 后缀；不覆盖原文件。

### 3.4 M3 智能去重模块

| 子模块 | 职责 | 备注 |
|--------|------|------|
| M3.1 特征提取器 | 从视频中提取三类比对特征：画面构图特征（关键帧深度特征向量）、运镜轨迹特征（运动/光流统计曲线）、剪辑节奏特征（镜头切分序列/节奏直方图） | 深度特征经 S2；传统特征经 S1 抽帧后本地计算 |
| M3.2 相似度计算器 | 计算待测素材与候选素材的综合重复度百分比及三个维度的分解得分；生成比对报告（相似视频列表 + 详情） | 加权融合，权重可配置 |
| M3.3 自动搜索对比 | 以本地素材特征为线索，经 M1 的平台插件搜索候选视频 → 下载候选（优先低清预览流）→ 特征比对；任一平台不可用时对该平台降级并在报告中标注"暂不可用"，整体功能不阻塞 | "尽力而为 + 可降级"定位 |
| M3.4 手动对比 | 用户指定本地对比视频文件（可多个），直接进入特征比对流程 | 与 3.3 可单独或结合使用 |
| M3.5 手法引擎 | 注册与管理 5 种手法实现：镜像翻转、画面裁切/缩放、调色/滤镜、变速处理、加边框；每种手法声明参数 Schema，负责参数校验与应用执行 | 模块化设计，新增手法只需注册新实现 |
| M3.6 策略管理器 | 预设方案三档（轻度 <50% / 中度 50%~80% / 重度 >80%），依据检测结果自动推荐档位，允许手动改选；自定义方案的创建、参数保存、套用；预设↔自定义随时切换 | 自定义方案存于 S3 |
| M3.7 去重流水线 | 按所选方案组合手法顺序执行 → 输出 `_deduped.mp4`；记录去重前后重复度对比数据供 UI 展示 | 经 M4 执行 |

输出约定：MP4；保存至工作目录下 `已去重/` 文件夹，内部保持与原素材相同的层级结构；原文件不动。

### 3.5 M4 任务调度中心

所有长耗时操作（下载、预处理、去重）的统一入口：

| 子模块 | 职责 |
|--------|------|
| M4.1 任务队列 | 任务入队、优先级、并发数控制；批量任务显示队列进度与单条状态 |
| M4.2 任务状态机 | `PENDING → RUNNING → SUCCESS / FAILED / SKIPPED / CANCELED`；状态每次变更先行持久化到 S3 |
| M4.3 重试控制器 | 失败自动重试，次数可配置；超限后标记该条失败/跳过，队列继续执行下一条（部分失败不影响整体） |
| M4.4 失败记录管理 | 失败统一写入失败列表（文件名、失败原因、失败时间）；提供"一键重新处理"入口（重建任务入队） |
| M4.5 崩溃恢复 | 启动时扫描数据库中遗留的 `RUNNING` 状态任务，标记为中断；可续传任务（下载）恢复续传，处理类任务进入失败列表等待重新处理；已完成文件不受影响 |

### 3.6 M5 素材库管理模块

| 子模块 | 职责 |
|--------|------|
| M5.1 工作目录管理 | 工作目录设定与校验；维护目录结构约定（原始区三级目录 + `已去重/` 镜像区） |

### 3.7 S1 媒体引擎服务

- FFmpeg 命令构建器与执行器（参数拼装、子进程生命周期、超时与错误码解析）；
- ffprobe 媒体信息解析（时长、分辨率、大小、音轨、字幕轨有无——支撑筛选与软/硬字幕判别）；
- 抽帧服务（按间隔/关键帧抽帧，供 AI 检测与传统特征计算）；
- 输出编码规范封装：统一 MP4（H.264 + AAC）。

### 3.8 S2 AI 推理服务

```text
InferenceProvider（抽象接口）
 ├── LocalProvider（本地实现，随安装包内置 ONNX 模型）
 │     · 水印检测模型：输出水印区域 BBox
 │     · 字幕检测模型：输出字幕行区域 BBox（中英文）
 │     · 图像修复模型：对遮罩区域进行内容填补
 │     · 特征提取模型：输出关键帧特征向量
 └── CloudProvider（预留扩展点，首版不实现）
```

职责：模型文件的懒加载与缓存、推理批处理、GPU/CPU 自适应（CPU 为基准）、推理结果后处理（BBox 合并、置信度过滤）。上层（M2/M3）只依赖抽象接口，不感知具体实现。

### 3.9 S3 数据持久化服务

SQLite 访问层：建表迁移、DAO 封装、事务保障。表结构见第六章。

### 3.10 S4 网络服务

HTTP 会话管理、代理配置、超时与限速策略、请求级重试；为平台插件与素材站 API 提供统一的网络出口（便于统一设置 UA、代理与流控）。

### 3.11 S5 基础服务

- 配置服务：应用设置的读写（存于 SQLite settings 表）；
- 日志服务：滚动文件日志，分级记录，用于问题排查；
- i18n 服务：语言包加载与切换（默认中文，支持英文），基于 Qt 翻译机制。

## 四、模块间关系

### 4.1 模块依赖图

```
U1 ──► M1 ──► 平台插件接口 ──► 各平台插件 ──► S4 ──► 外部网络
U2 ──► M2 ──► S2（检测/修复） 、S1（变换/剥离音轨）
U3 ──► M3 ──► M1（复用搜索能力做自动对比） 、S2（特征提取） 、S1（手法执行）

U* ──► M4（所有长任务的提交入口）          M1/M2/M3 ──► M4（作为任务执行方被调度）
M1（归档）──► M5 ◄── M2/M3（输出落盘）      U1/U2/U3 列表数据 ──► M5（素材索引）
全部业务模块 ──► S3 / S5                   S1/S2/S3/S4/S5 为被依赖的基础设施
```

要点说明：

1. **UI 层不直接驱动任务**：U1/U2/U3 只向 M4 提交任务描述并订阅进度信号，保证界面响应性；
2. **M3 → M1 的单向复用**：智能去重的"自动搜索对比"复用 M1 的搜索与下载能力（含插件体系与筛选器），这是业务模块间唯一的横向依赖，且方向固定、经 M4 编排，不允许 M1 反向依赖 M3；
3. **平台插件是 M1 的扩展点**：新增平台 = 新增一个插件实现，M1 其余部分不变；
4. **手法是 M3 的扩展点**：新增去重手法 = 注册一个新的 Technique 实现；
5. **S2 是 AI 能力的唯一出入口**：M2/M3 不直接接触模型文件，便于未来接入云端 Provider。

### 4.2 核心业务流程

#### 流程 A：素材搜索与下载（找素材）

```
用户输入关键词 → U1 提交搜索请求 → M1.1 分发至启用平台插件（国内外分区）
   ├─ 国外平台未开启外网能力 → M1.5 探测 → UI 弹窗提示
   └─ 返回 VideoMeta 列表 → M1.2 筛选 → U1 预览列表
用户勾选 + 设置数量上限 → 提交下载任务至 M4 → M1.3 队列并发下载（断点续传）
   → 完成 → M5.2 三级目录归档命名 → M5.3 更新素材索引 → U1 显示结果
```

#### 流程 B：视频预处理（洗素材）

```
用户在 U2 勾选素材与处理项（可手动框选水印/字幕区域）
→ 提交 M4 → M2.1 组装流水线逐条执行：
   去水印：S1 抽帧 → S2 检测 BBox（或用框选遮罩）→ S2 修复 → 回写帧序列
   去字幕：软字幕 → S1 剥离轨道；硬字幕 → 同水印流程
   裁剪/比例/去原声 → S1 滤镜执行
→ M5.4 原子写出 `xxx_cleaned.mp4`（同目录）→ 结果列表回传 U2
失败条目 → 重试控制器 → 超限进入失败列表
```

#### 流程 C：智能去重（过原创）

```
用户在 U3 选择素材与对比方式（自动搜索 / 手动指定 / 结合）
→ 提交 M4 → M3.1 特征提取 → 相似度计算 → 重复度报告
→ M3.6 推荐档位（<50 轻度 / 50~80 中度 / >80 重度）或用户自选/自定义方案
→ M3.7 组合手法执行（镜像/裁缩放/调色/变速/边框）→ S1 编码输出
→ M5 写入 `已去重/<镜像层级>/xxx_deduped.mp4`
→ 记录去重前后重复度对比 → U3 展示报告
自动搜索对比中某平台不可用 → 该平台降级标注，其余继续
```

### 5.1 平台适配插件接口（扩展点一）

```python
class PlatformPlugin(Protocol):
    # 元信息
    id: str                # 如 "douyin"
    display_name: str
    region: Literal["cn", "global"]

    def check_available(self) -> bool: ...
        # 平台可达性探测（配合 S4 网络服务）

    def search(self, keyword: str, filters: SearchFilters,
               max_count: int) -> list[VideoMeta]: ...
        # 返回统一结构的搜索结果（时长/分辨率/大小/水印标记/缩略图 URL 等）

    def download(self, video: VideoMeta, dest_path: str,
                 on_progress: Callable[[float], None],
                 resume_state: ResumeState | None) -> ResumeState: ...
        # 支持断点续传；resume_state 记录已完成字节/分片信息
```

约束：插件不得直接操作 UI；一切网络行为经由 S4；下载产物交由 M5 归档。

class DedupTechnique(Protocol):

    def apply(self, ctx: ClipContext, params: dict) -> ClipContext: ...

## 七、非功能性设计

### 7.1 性能设计与指标映射

| 需求指标 | 设计措施 |
|----------|----------|
| 批量下载 ≥3 并行 | M1.3 下载队列并发数默认 3，可在设置中调大 |
| 启动 ≤5s | UI 先行展示；模型懒加载；插件按需初始化；DB 延迟打开 |
| 界面响应 ≤1s | 所有耗时操作在工作线程；UI 仅消费信号刷新 |
| 预处理 ≤2× 视频时长 | 流水线一次解码串联多项处理（避免多次转码）；检测模型按帧间隔抽样后映射回时间线；修复仅在遮罩区域局部进行 |
| 去重 ≤3× 视频时长 | 手法尽量以 FFmpeg 滤镜图一次性串接执行；特征提取复用同一批抽帧结果 |

### 7.2 稳定性设计

- **非破坏性原则**：原始素材只读；所有输出走"临时文件 + 原子重命名"，杜绝半成品文件；
- **崩溃不丢数据**：任务状态先写库再执行；重启后 `interrupted` 任务可恢复或转入失败列表；
- **隔离性**：FFmpeg 以子进程运行，异常不拖垮主程序；单条任务失败不影响队列其余任务。

### 7.3 异常处理机制映射

| 需求异常场景 | 设计机制 |
|--------------|----------|
| 单条处理失败 | M4.3 自动重试（次数可配），超限标记跳过，继续下一条 |
| 下载中断 | M1.3 断点续传（resume_state 持久化） |
| 网络连接异常 | S4 请求级重试 + 明确错误提示与"手动重试"入口 |
| 平台接口变动 | 插件 check_available 失败 → 该平台标记"暂时不可用"，记录失败列表，不影响其他平台 |
| 批量部分失败 | M4 队列隔离，失败条目入失败列表 |
| 软件崩溃 | M4.5 启动扫描中断任务；已完成文件因原子写入而完好 |

### 7.4 兼容性与国际化

- 系统：Windows 10+；安装包内自带 FFmpeg 与模型，无需用户另装依赖；
- 输入格式：MP4/AVI/MOV/MKV/FLV（由 ffprobe 探测，不识别的格式给出明确提示）；
- 输出规格：MP4（H.264 + AAC）统一封装于 S1；
- 语言：中文默认、英文可选，语言包独立于代码，设置中即时切换。

### 7.5 安全与合规设计

- 工具本身不存储、不传播版权内容，素材均存于用户本地工作目录；
- Pexels/Pixabay 的 API Key 由用户在设置页自行填写，本地加密存储，不硬编码进开源仓库；
- 日志不记录用户敏感信息。

## 九、设计风险与对策

| 风险 | 设计对策 |
|------|----------|
| 平台反爬升级致采集失效 | 插件化隔离，热更新单一插件即可修复；插件 check_available 快速暴露故障 |
| AI 去水印/去字幕效果不完美 | 自动+手动双模式互补；处理前预览确认；修复限定遮罩局部降低画质损伤 |
| 自动搜索比对受平台限制 | "尽力而为+可降级"定位；手动对比兜底；报告透明标注各平台可用状态 |
| Python 打包体积大（含模型） | 模型选轻量级 ONNX；后续可按需拆分"基础包+模型包"下载 |
| GIL 影响批量吞吐 | FFmpeg 子进程 + 推理库释放 GIL；必要时处理任务升级为子进程池 |
